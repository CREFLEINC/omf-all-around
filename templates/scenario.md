## 실행 기록

| 단계·시도 | 실행 시각·시간대 | 채널·액션·검증 방식(UI/API) | 기대 결과 | 실제 결과 | 캡처 또는 요청/응답 증거 링크 | 통과/실패/미검증·증거 누락 |
|---|---|---|---|---|---|---|

initial/final의 관리자 웹 액션은 직전과 실행 후 결과 화면을 저장한다. recheck는 스크린샷 없이 결과와 필요한 근거만 기록한다. POP·모바일 액션은 실제 클라이언트 요청을 기준으로 API를 호출하고 시각·메서드·경로·역할·비밀값 제외 요청/응답·상태 코드를 저장한다. 비동기 완료 조건과 응답·재조회 근거는 해당 단계에 함께 적는다.
파일명: <단계>-<시도>-before.png / <단계>-<시도>-after.png. 처리 중 캡처는 during-<번호>.png로 추가한다.
첫 실행 전체 통과 시 해당 기록이 최종 증거이며 재실행하지 않는다. 수정 중에는 실패 구간만 확인하고 수정 완료 후 처음부터 끝까지 final을 실행한다. 각 실행은 별도 ID로 기록하고 이전 증거를 보존한다. recheck의 캡처 생략은 계획된 생략이며 initial/final 캡처 불가 시 사유를 남긴다. final 실패 시 완료 처리하지 않는다.
