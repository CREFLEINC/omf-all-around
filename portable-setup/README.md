# 새 PC에 파이널 루틴 심기

이 폴더는 클라이언트 13개·서버 6개 하네스 파일의 복사본이다. 원본은 `files/`, 원본 커밋과 파일 해시는 `manifest.json`에 있다. 제품 소스·비밀값·DB·기존 실행 증거는 포함하지 않는다.

## 사용자

1. 이 통합 관리 프로젝트와 클라이언트·서버 저장소를 clone한다.
2. 아래 명령의 경로를 실제 clone 위치로 바꾸거나 새 세션에 적용을 맡긴다.
3. `.env`의 필요한 값, 기기 연결·OS 승인 등은 별도로 준비한다.

## 에이전트

```sh
python3 portable-setup/install.py --client /path/to/omf-mes-client --server /path/to/omf-mes-server
python3 portable-setup/install.py --client /path/to/omf-mes-client --server /path/to/omf-mes-server --apply
```

첫 명령은 확인만 한다. 두 번째는 전체 사전 검사 후 기존 파일을 이 프로젝트의 `backups/portable-*/`에 백업하고 적용한다. 최신 저장소 파일이 원본 기준과 다르면 전체 적용을 중단한다. 그 경우 에이전트가 차이를 검토해 현재 코드에 맞게 병합한다. 오래된 스냅샷을 강제로 덮어쓰지 않는다.

각 저장소의 `.final-routine/WORKFLOW.md`와 시작 지침을 함께 설치한다. 이어서 그 문서에 따라 의존성·환경 변수·DB·서버·단말을 준비한다. 설치 스크립트는 이를 실행하거나 제품 코드를 복원하지 않는다. 모델은 새 환경에서 실제 지원 여부를 확인한다.

복구 시 `restore-manifest.json`에서 `existed: true` 파일은 백업을 복사하고, `false` 파일은 설치 후 추가 수정이 없는지 확인해 제거한다. 자동 강제 복구는 하지 않는다.

## GitHub 보관 범위

통합 관리 저장소에는 이 복원 묶음과 공통 워크플로 문서만 올린다. 설치된 하네스는 클라이언트·서버 제품 PR에 포함하지 않는다. 제품 계약 선행 변경 장부는 예외적으로 제품 PR에 포함해야 한다.

루트 `.gitignore`는 허용 목록 방식이다. `.env`, DB 백업, 증거, APK, 과거 세션 기록은 기본 제외한다. 새 공유 파일이 필요하면 내용을 검토한 뒤 허용 목록에 추가한다. 실제 push 전 staged diff를 확인한다.
