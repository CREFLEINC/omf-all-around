# 파이널 루틴 모델 배정 — 멀티 플랫폼

사용자가 작업별 효율적 모델 선택을 위임했다. 이 프로젝트는 **ChatGPT/Codex 계열과 Claude Code 계열을 모두** 실행 환경으로 쓴다. 아래 표는 업무 난도를 기준으로 삼고, 각 플랫폼의 실제 노출 모델을 그 난도에 대응시킨다.

이 문서 자체가 모델을 변경하지는 않는다. 실제 선택은 담당 세션을 만들거나 다음 지시를 보낼 때 지정한다. **현재 환경에서 실제로 지원되는 모델인지 먼저 확인하고, 없으면 바뀌었다고 주장하지 않고 제한을 보고한다.**

## 난도 등급과 플랫폼별 대응

| 등급 | 업무 | ChatGPT/Codex | Claude Code | 추론·노력 수준 |
|---|---|---|---|---|
| **A. 판단** | 시나리오·데이터 흐름 설계, 어려운 정합 판단, 통합 담당 | `gpt-6-astra` | `claude-opus-5` (Opus 5) | high / xhigh |
| **B. 구현** | 일반 클라이언트·서버 개발, 원인 조사 | `gpt-5.6-terra` | `claude-sonnet-5` (Sonnet 5) | medium, 어려우면 high |
| **C. 실행** | 정해진 관리자 웹/API 테스트 실행, 증거 정리, 아주 작은 수정 | `gpt-5.6-luna` | `claude-haiku-4-5-20251001` (Haiku 4.5) | low, 화면 판단 시 medium |
| **D. 난구현** | B에서 해결되지 않는 복합 구현 | `gpt-5.6-sol` | `claude-opus-5` (Opus 5) | high |

- D 등급에서 원인·규격 판단이 필요해지면 A로 올린다. Claude Code는 B의 상위가 곧 A와 같은 모델이므로, 등급 상승은 **모델이 아니라 노력 수준(`/effort`)으로 먼저** 조정하고 그래도 막히면 Opus로 올린다.
- Claude Code의 긴 컨텍스트가 필요한 통합 담당은 1M 변형(`opus[1m]`)을 쓴다.
- 두 계열의 등급이 대응한다는 뜻이지 품질·비용이 같다는 뜻은 아니다. 실측 비용·실패율을 보며 조정한다.

공식 모델 설명: ChatGPT <https://learn.chatgpt.com/docs/models?surface=app> · Claude <https://docs.claude.com/en/docs/about-claude/models>

## 플랫폼별 지정 방법

| | ChatGPT/Codex | Claude Code |
|---|---|---|
| 세션 생성 시 | 세션 생성 옵션에서 모델 지정 | `claude --name <이름> --model <모델> --effort <수준>` |
| 세션 중 변경 | 다음 지시에 모델 명시 | `/model`, `/effort` |
| 단기 위임 | 실행 에이전트 생성 시 지정 | Agent 도구 `model` 인자 (`opus`/`sonnet`/`haiku`) |

Claude Code 보충:
- 팀원(agent team)은 리더의 노력 수준을 상속한다. `/model`·`/fast`는 리더에만 적용되고 팀원 모델은 생성 시 고정된다.
- 팀원 모델 우선순위: 스폰 프롬프트 지정 → 서브에이전트 정의의 `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → 리더 모델.
- in-process 팀원 요청은 메인 대화의 캐시 버킷 밖이라 기본 5분 TTL이다. 장시간 도구 대기가 잦으면 `subagentPromptCacheTtl: "1h"`를 검토한다(1h 캐시 쓰기는 더 비싸다).

## 공통 운영 규칙 (플랫폼 무관)

- 개발 담당 세션은 유지하고 다음 작업 성격에 맞춰 모델을 지정한다. 장시간 도구 대기를 위해 고비용 에이전트를 별도 추가하지 않는다.
- 실행 에이전트는 명세·코드 수정 없이 실제 실행/결과 보고만 수행한다. 제품 오류는 개발 담당에게 넘기고, 절차 해석이나 조작 한계는 상위 등급으로 전환한다.
- 단기 에이전트에는 지침 경로, cwd, 시나리오/버전, 시작 상태, 데이터 변수, 기대 결과, 중단 조건, 증거 경로를 전달한다. 부모 전체 대화를 무조건 복제하지 않는다.
- 실행 담당은 관리자 웹을 실제 조작할 수 있는 도구와 로컬 증거 저장 수단이 있는지 먼저 확인한다. 단순 API 실행으로 관리자 웹 검증을 대체하지 않는다.
- 동일 브라우저/테스트 데이터는 한 실행자만 조작한다. 수정·재시작과 실행을 조정한다.
- 작업 기록에 실제 지정한 플랫폼·모델·추론 수준·전환 사유를 남긴다. 가격/토큰 수를 추측해 비용 절감을 보고하지 않는다.
- 단순 작업에 고비용 모델을 일괄 사용하지 않는다. 같은 실패를 저렴한 모델로 반복해 시간을 낭비하지도 않는다.
